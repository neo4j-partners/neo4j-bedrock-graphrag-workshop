= Lab 4 Instructions: Strands GraphRAG Agent and AgentCore

Follow this notebook to build a Strands agent that wraps the Lab 3 `VectorCypherRetriever` as a tool, test it locally against your knowledge graph, then deploy it to Amazon Bedrock AgentCore Runtime and invoke it over REST.

TIP: For concepts and background, see xref:lab4.adoc[Lab 4: Strands GraphRAG Agent and AgentCore].

== What You'll Learn

* **Wrap retrieval as a tool**: expose the Lab 3 `VectorCypherRetriever` as a Strands `@tool` function
* **Build and test the agent**: create an `Agent` with a `BedrockModel` and the retrieval tool, then run natural-language SEC 10-K questions locally
* **Deploy to AgentCore**: package and deploy the agent with `direct_code_deploy` from the bedrock-agentcore-starter-toolkit
* **Invoke remotely**: call the deployed agent through its REST endpoint via boto3 and the agentcore CLI

== Prerequisites

* Completed **Lab 3** (or at least the Lab 1 seed load, which provides the chunks, Titan v2 embeddings, and the `chunkEmbeddings` index the agent's tool queries)
* Completed the **Part 2 environment setup**: see xref:part2-setup-instructions.adoc[Part 2 Setup Instructions]
* `CONFIG.txt` filled in with your Neo4j credentials; `MODEL_ID` and `REGION` use working defaults

NOTE: The AgentCore deployment relies on IAM resources the workshop administrator provisions ahead of time, including the runtime execution role. See xref:admin-setup.adoc[the admin setup guide] for details. In hosted OneBlink environments the deploy step may lack the permissions to create the runtime; if so, review the deployment code to understand each step, then run the full deploy later in your own AWS account.

=== Walkthrough: Notebook 01 (build and test)

. **Build the retrieval tool.** Wrap the Lab 3 `VectorCypherRetriever` in a Python function decorated with `@tool`. The function embeds the query, runs vector search over the `chunkEmbeddings` index, traverses the graph to companies, products, and risk factors, and returns the formatted context. Write the docstring as instructions to the model.
. **Assemble the agent.** Create a Strands `Agent` with a `BedrockModel` and the retrieval tools, then give it a system prompt that frames it as a SEC 10-K analyst.
. **Test locally.** Ask natural-language questions such as the workshop's hero question and confirm the agent calls the tool, traverses the graph, and returns grounded answers.

=== Walkthrough: Notebook 02 (deploy, optional)

. **Fill the package from `CONFIG.txt`.** The notebook reads your Neo4j credentials and writes them into `agentcore_deploy/agent.py`, so you never retype the values from Lab 1. The populated `agent.py` is git-ignored.
. **Deploy to AgentCore.** Use `direct_code_deploy` from the bedrock-agentcore-starter-toolkit. The deployment package is the agent code (`agent.py`) plus `pyproject.toml`, and the `.bedrock_agentcore.yaml` config specifies the entrypoint, runtime, and IAM execution role. Running the deploy packages the code, uploads it to S3, and creates the runtime.
. **Invoke remotely.** Call the deployed agent through its REST endpoint using the `bedrock-agentcore` boto3 client's `invoke_agent_runtime` with the agent ARN, or through the `agentcore` CLI.
