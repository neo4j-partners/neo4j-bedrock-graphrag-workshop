= Lab 5 Instructions: Agent Memory with Neo4j

Follow these steps to add short-term and long-term memory to the Lab 4 GraphRAG agent using the neo4j-agent-memory library. The memory graph lives in the same Neo4j Aura instance as the SEC 10-K knowledge graph, so the agent reads its domain knowledge and its conversation state from one connection.

The lab is two notebooks in `Lab_5_Agent_Memory/`:

* `01_short_term_memory.ipynb`: the conversational recall layer.
* `02_long_term_memory.ipynb`: the durable knowledge layer.

TIP: For concepts and background, see xref:lab5.adoc[Lab 5: Agent Memory with Neo4j].

== What You'll Learn

* **Configure memory**: build a `MemoryClient` against the existing Aura instance using Titan Text Embeddings V2
* **Write to memory**: record each question and answer in short-term memory after a turn completes
* **Read from memory**: inject prior conversation context into the prompt before each invocation
* **Persist knowledge**: store entities, facts, and preferences that survive across sessions
* **Verify in Neo4j**: inspect the memory nodes in Neo4j Browser

* Completed **Lab 4**: the GraphRAG agent from xref:lab4.adoc[Lab 4: Strands GraphRAG Agent and AgentCore], running locally or deployed

== Notebook 1: Short-Term Memory

=== 1. Build and Connect the MemoryClient

`neo4j-agent-memory` is asynchronous, so every memory call is awaited. The Lab 5 helper reads `CONFIG.txt` and wires a client over the existing Aura instance with Titan embeddings. Open it, then connect.

[source,python]
----
from graphrag_agent import build_graphrag_agent
from lib.memory_utils import build_memory_client

graphrag = build_graphrag_agent()   # the Lab 4 agent, imported not rebuilt
agent = graphrag.agent

memory = build_memory_client()
await memory.connect()
----

=== 2. Wrap the Agent with Memory

Two lines of memory work surround each agent call: read context before, write the turn after. Clearing `agent.messages` each turn means the continuity you see comes from Neo4j-backed memory, not the model's own context window.

[source,python]
----
async def ask(question: str, session_id: str) -> str:
    context = await memory.get_context(question, session_id=session_id)
    prompt = f"{context}\n\nUser question: {question}" if context else question

    agent.messages = []
    answer = str(agent(prompt))

    await memory.short_term.add_message(session_id, "user", question)
    await memory.short_term.add_message(session_id, "assistant", answer)
    return answer
----

=== 3. Run the Three-Turn Demo

Call the memory-wrapped agent three times in one session and watch each turn build on the last:

[source,python]
----
SESSION = "apple-research"
await ask("Tell me about Apple's risk factors.", SESSION)
await ask("What about their competitors?", SESSION)
await ask("Summarize what we discussed.", SESSION)
----

* **Turn 1** answers from GraphRAG retrieval against the 10-K graph.
* **Turn 2** resolves "their" to Apple using short-term memory, then answers about Apple's competitors.
* **Turn 3** returns a coherent summary that spans both prior turns.

=== 4. Inspect the Conversation in Neo4j

The memory client exposes the graph via `memory.graph`. Read back this session's messages:

[source,python]
----
rows = await memory.graph.execute_read(
    """
    MATCH (c:Conversation {session_id: $session_id})-[:HAS_MESSAGE]->(m:Message)
    RETURN m.role AS role, m.content AS content, m.timestamp AS timestamp
    ORDER BY m.timestamp
    """,
    {"session_id": SESSION},
)
----

The `Conversation` and `Message` nodes sit in the same database as the `Company`, `Product`, and `RiskFactor` nodes from the 10-K graph.

== Notebook 2: Long-Term Memory

Long-term memory holds durable knowledge that outlives a single conversation. Write entities, facts, and preferences explicitly:

[source,python]
----
from neo4j_agent_memory.memory.long_term import EntityType

entity, dedup = await memory.long_term.add_entity(
    name="Apple", entity_type=EntityType.ORGANIZATION,
)
fact = await memory.long_term.add_fact(
    subject="Apple", predicate="COMPETES_WITH", obj="Microsoft",
)
pref = await memory.long_term.add_preference(
    category="analysis", preference="Prefers concise risk summaries as bullet points.",
)
----

Then recall them from a fresh session, proving the knowledge is stored rather than tied to a conversation:

[source,python]
----
entities = await memory.long_term.search_entities("technology company", limit=5)
context = await memory.long_term.get_context("What do we know about Apple?")
----

An optional cell uses `adopt_existing_graph` to layer long-term memory over the existing SEC 10-K `Company` nodes, so later mentions link to the companies you already have instead of duplicates.
