Follow these steps to add short-term and long-term memory to the Lab 4 GraphRAG agent using the neo4j-agent-memory library. == Notebook 1: Short-Term Memory

=== 1. Build and Connect the MemoryClient

`neo4j-agent-memory` is asynchronous, so every memory call is awaited. The Lab 5 helper reads `CONFIG.txt` and wires a client over the existing Aura instance with Titan embeddings. Open it, then connect.

[source,python]
----
from graphrag_agent import build_graphrag_agent
from lib.memory_utils import build_memory_client

graphrag = build_graphrag_agent()   # the Lab 4 agent, imported not rebuilt
agent = graphrag.agent

memory = build_memory_client()
await memory.connect()
----

=== 2. Wrap the Agent with Memory

Two lines of memory work surround each agent call: read context before, write the turn after. Clearing `agent.messages` each turn means the continuity you see comes from Neo4j-backed memory, not the model's own context window.

[source,python]
----
async def ask(question: str, session_id: str) -> str:
    context = await memory.get_context(
        question,
        session_id=session_id,
        include_long_term=False,
        include_reasoning=False,
    )
    prompt = f"{context}\n\nUser question: {question}" if context else question

    agent.messages = []
    answer = str(agent(prompt))

    await memory.short_term.add_message(session_id, "user", question)
    await memory.short_term.add_message(session_id, "assistant", answer)
    return answer
----

=== 3. Run the Three-Turn Demo

Call the memory-wrapped agent three times in one session and watch each turn build on the last:

[source,python]
----
SESSION = "apple-research"
await ask("Tell me about Apple's risk factors.", SESSION)
await ask("What about their competitors?", SESSION)
await ask("Summarize what we discussed.", SESSION)
----

* **Turn 1** answers from GraphRAG retrieval against the 10-K graph.
* **Turn 2** resolves "their" to Apple using short-term memory, then answers about Apple's competitors.
* **Turn 3** returns a coherent summary that spans both prior turns.

=== 4. Inspect the Conversation in Neo4j

The memory client runs read-only Cypher via `memory.query.cypher`, which works on both the bolt and hosted backends. Read back this session's messages:

[source,python]
----
rows = await memory.query.cypher(
    """
    MATCH (c:Conversation {session_id: $session_id})-[:HAS_MESSAGE]->(m:Message)
    RETURN m.role AS role, m.content AS content, m.timestamp AS timestamp
    ORDER BY m.timestamp
    """,
    {"session_id": SESSION},
)
----

The `Conversation` and `Message` nodes sit in the same database as the `Company`, `Product`, and `RiskFactor` nodes from the 10-K graph.

== Notebook 2: Long-Term Memory

Long-term memory holds durable knowledge that outlives a single conversation. There is no automatic extractor: the memory client is configured with `ExtractorType.NONE`, so nothing is inferred from raw text. You write each entity, fact, and preference explicitly with `add_entity`, `add_fact`, and `add_preference`.

=== 1. Write Durable Knowledge

Three explicit write methods cover the three kinds of long-term memory. `add_entity` returns an `(entity, dedup_result)` tuple: the second value tells you whether the entity was newly created or merged into an existing one, exposed as `dedup.action`. `add_fact` takes its object via the `obj=` argument. `add_preference` records how the user wants answers shaped.

[source,python]
----
from neo4j_agent_memory.memory.long_term import EntityType

# An entity worth remembering across sessions.
entity, dedup = await memory.long_term.add_entity(
    name="Apple",
    entity_type=EntityType.ORGANIZATION,
    description="Consumer electronics and services company; SEC 10-K filer.",
)
print(f"Entity: {entity.name} ({entity.type}) - dedup action: {dedup.action}")

# A fact: subject, predicate, object.
fact = await memory.long_term.add_fact(
    subject="Apple",
    predicate="COMPETES_WITH",
    obj="Microsoft",
)
print(f"Fact: {fact.subject} {fact.predicate} {fact.object}")

# A preference: how this user likes their answers.
pref = await memory.long_term.add_preference(
    category="analysis",
    preference="Prefers concise risk summaries as bullet points.",
)
print(f"Preference [{pref.category}]: {pref.preference}")
----

=== 2. Recall in a Fresh Session

The knowledge above was written with no `session_id`, so it belongs to the store rather than to a conversation. A brand-new session can still find it. Each write method has a matching semantic lookup: `search_entities`, `search_facts`, and `search_preferences`. They match by meaning rather than exact wording, and `long_term.get_context` bundles the relevant entities and preferences into one string ready for an LLM prompt.

[source,python]
----
entities = await memory.long_term.search_entities(
    "technology company", limit=5, threshold=0.5
)
facts = await memory.long_term.search_facts(
    "Who does Apple compete with?", limit=5, threshold=0.5
)
prefs = await memory.long_term.search_preferences(
    "How should answers be formatted?", limit=5, threshold=0.5
)

context = await memory.long_term.get_context("What do we know about Apple?")
----

Each lookup ranks by vector similarity, so it takes a `threshold`. The default is `0.7`. A topical query such as "technology company" rarely scores as high against a stored name as an exact match would, so the notebook passes `threshold=0.5` to accept a semantically related result. Raise the threshold toward `0.7` for stricter, higher-precision recall; lower it to cast a wider net.

=== 3. Optional: Adopt the Existing SEC Graph

The graph already holds `Company` nodes from the SEC 10-K seed load. This optional cell uses `adopt_existing_graph` to layer long-term memory over those existing nodes instead of creating parallel `Entity` nodes, so when a message later mentions "Apple" it links to the company you already have rather than a duplicate. The operation is idempotent.

`adopt_existing_graph` takes a `label_to_type` map (node label to memory entity type) and a `name_property_per_label` map (which property holds each label's name). It returns a report whose `total_migrated`, `total_already_adopted`, and `total_skipped` fields tally what happened.

[source,python]
----
report = await memory.schema.adopt_existing_graph(
    label_to_type={"Company": "ORGANIZATION"},
    name_property_per_label={"Company": "name"},
)
print(
    f"Adopted {report.total_migrated} nodes "
    f"({report.total_already_adopted} already adopted, {report.total_skipped} skipped)."
)
----
