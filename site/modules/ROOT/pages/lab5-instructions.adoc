= Lab 5 Instructions: Agent Memory with Neo4j

Follow these steps to add short-term and long-term memory to the Lab 4 GraphRAG agent using the neo4j-agent-memory library. The memory graph lives in the same Neo4j Aura instance as the SEC 10-K knowledge graph, so the agent reads its domain knowledge and its conversation state from one connection.

NOTE: The hands-on notebook for this lab is in development. The `Lab_5_Agent_Memory/` directory will hold it when it ships. The steps below describe the design and the code you will run, so you can follow the flow now and execute it once the notebook lands.

TIP: For concepts and background, see xref:lab5.adoc[Lab 5: Agent Memory with Neo4j].

== What You'll Learn

* **Configure memory**: point a `MemoryClient` at the existing Aura instance using Titan Text Embeddings V2
* **Write to memory**: record each question and answer in short-term memory after a turn completes
* **Read from memory**: inject prior conversation context into the prompt before each invocation
* **Verify in Neo4j**: inspect the `Conversation`, `Message`, and `Entity` nodes in Neo4j Browser

== Prerequisites

* Completed **Lab 4**: the GraphRAG agent from xref:lab4.adoc[Lab 4: Strands GraphRAG Agent and AgentCore], deployed or running locally
* Completed the **Part 2 environment setup**: see xref:part2-setup-instructions.adoc[Part 2 Setup Instructions]

NOTE: This lab uses the same Neo4j Aura instance and the same Bedrock configuration as Part 2. The memory layer adds `Conversation`, `Message`, and `Entity` nodes to that database. It does not clear or reload the 10-K knowledge graph.

=== CONFIG.txt

The memory client reads the same credentials as the earlier labs. Confirm `CONFIG.txt` at the repository root has your Neo4j connection details and the Bedrock region:

[source,text]
----
NEO4J_URI=neo4j+s://xxxxxxxx.databases.neo4j.io
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your-password-from-lab-0
REGION=us-east-1
----

The embedding model is Amazon Titan Text Embeddings V2 (`bedrock/amazon.titan-embed-text-v2:0`), which produces 1024-dimensional vectors. No new models are needed.

== Steps

=== 1. Configure the MemoryClient

Point a `MemoryClient` at the existing Aura instance and set Titan Text Embeddings V2 as the embedder. This is the same database and the same embedding model already in use, so there is nothing new to provision.

[source,python]
----
from neo4j_agent_memory import MemoryClient

memory = MemoryClient(
    neo4j_uri=NEO4J_URI,
    neo4j_username=NEO4J_USERNAME,
    neo4j_password=NEO4J_PASSWORD,
    embedding_model="bedrock/amazon.titan-embed-text-v2:0",
    conversation_id="lab5-demo",
)
----

=== 2. Write Each Turn to Memory

After the Lab 4 agent produces an answer, record both the question and the answer in short-term memory. Wrapping the existing agent call keeps the GraphRAG tool unchanged; memory is added around it.

[source,python]
----
def answer_with_memory(question: str) -> str:
    # inject prior context (step 3), then run the Lab 4 agent
    answer = graphrag_agent(question)

    # write this turn to short-term memory
    memory.add_message(role="user", content=question)
    memory.add_message(role="assistant", content=answer)

    return answer
----

=== 3. Inject Prior Context Before Each Invocation

Before the agent runs, call `get_context` to pull relevant prior conversation from memory and prepend it to the prompt. This is what lets the agent resolve references like "their" to the entity from an earlier turn.

[source,python]
----
def answer_with_memory(question: str) -> str:
    context = memory.get_context(query=question)

    prompt = f"""Prior conversation:
{context}

Current question: {question}"""

    answer = graphrag_agent(prompt)

    memory.add_message(role="user", content=question)
    memory.add_message(role="assistant", content=answer)

    return answer
----

=== 4. Run the Three-Turn Demo and Inspect the Graph

Call the memory-wrapped agent three times in sequence and observe how each turn builds on the last:

[source,python]
----
answer_with_memory("Tell me about Apple's risk factors.")
answer_with_memory("What about their competitors?")
answer_with_memory("Summarize what we discussed.")
----

* **Turn 1** answers from GraphRAG retrieval against the 10-K graph.
* **Turn 2** resolves "their" to Apple using short-term memory, then answers about Apple's competitors.
* **Turn 3** returns a coherent summary that spans both prior turns.

Then open Neo4j Browser and run:

[source,cypher]
----
MATCH (c:Conversation {id: "lab5-demo"})-[:HAS_MESSAGE]->(m:Message)
RETURN c, m
----

The `Conversation`, `Message`, and `Entity` nodes appear in the same database as the `Company`, `Product`, and `RiskFactor` nodes from the 10-K graph, so you can see conversation state and domain knowledge side by side.
